# AGENTS.md

Instructions for AI coding agents working in this repository. Every line answers: "would you get this wrong without being told?" Verified against the toolchain on 2026-09-16.

## Commands

Run from the repo root. Bun is the canonical package manager — never mix `npm`/`yarn`/`pnpm` installs (the committed `bun.lock` is the resolution for exactly the committed `package.json`).

| Command | What it does |
|---|---|
| `bun install` | Install dependencies |
| `bun run dev` | Dev server on :3000 (Turbopack) |
| `bun run build` / `bun run start` | Production build / serve (build before start) |
| `bun run lint` | ESLint 9 flat config — must exit 0 |
| `bun run typecheck` | `tsc --noEmit` — must exit 0 |
| `bun run test` / `bun run test:watch` | Vitest unit suite (434 tests) / watch mode |
| `bun run test:e2e` | Playwright E2E gate: `next build` + 67 browser specs against the production build on :3100 (hermetic `db/e2e.db`; the dev DB is never touched; `FINARA_INSIGHTS_LLM_OFF=1` keeps the insights generation deterministic) |
| `bun run test:e2e:headed` | Same, headed (debugging) |
| `bun run db:push` | Push `prisma/schema.prisma` to SQLite (creates `db/custom.db`) |
| `bun run db:generate` | Regenerate the Prisma client after schema edits |
| `bun run db:migrate` / `db:reset` | Dev migrations / drop+recreate (SQLite) |
| `bun run db:deploy` | `prisma migrate deploy` — apply the committed baseline (production deploys; round 15) |

Setup order: `cp .env.example .env` → `bun install` → `bun run db:push` → `bun run dev`. No manual seeding — the first API request runs `ensureSeeded()` (idempotent, concurrency-safe).

Push contract: `main` only, via `python3 docs/ssh_git_wrapper_v3.py --key-file <path outside repo> --remote git@github.com:nordeim/financial-dashboard.git` — never commit the key (`.gitignore` rejects `*.key` / `ssh-key.txt` / `.env*`). Run `bun run lint && bun run typecheck && bun run test && bun run test:e2e` green before pushing (CI runs the same chain — `.github/workflows/ci.yml`). See `docs/how-to-git-push-using-ssh-wrapper_SKILL.md`.

## Architecture invariants

- **The app serves the live REAL ROUTES (ADR-021).** `src/app/page.tsx` serves `/` and `src/app/[...view]/page.tsx` maps every other path through `src/lib/routes.ts` (`VIEW_PATHS`, `parseRoute`, `segmentToTitle`) with `generateMetadata` titles; `FinaraApp` switches views by `ViewId` state inside a single mount (SPA via `history.pushState`/`popstate`, anchors `preventDefault`). Only `/api/*` handlers are additional routes — do not add per-view page folders (they remount the app).
- **Money is SIGNED integer minor units (ADR-024, round-11).** Every persisted amount is `amountMinor: Int` (cents), and **negatives are valid end-to-end** — the live app has zero amount validation (probed: negative expenses/income/accounts/goals/investments all persist and render `-$5.50` style; negative contributions to goals are a silent no-op, PUT 200 unchanged). `toMinorUnits` accepts negative strings, the API guards are `requireSignedInt`/`requireFiniteNumber` (NOT non-negative/positive), NO numeric form input carries `min="0"`, and the IMPORT path follows the same rule (round-12: rows mode keeps only the integer-shape guard; `normalizeFinaraExport` restores negative decimals). The expense row renders the live's double-minus quirk (`--$5.50`) for negatives, `formatMoney` renders `-$0.00` for −0. Do not re-add positivity validation at any layer — it diverges from the live app.
- **API envelope.** Every route returns `{ ok: true, data } | { ok: false, error }` via `src/lib/api.ts` helpers (`ok`, `fail`, `errorResponse`). Validate input with the `require*` guards; never throw across the boundary.
- **The HTTP/metadata layer is pinned too (round 17, live-probed 2026-09-19; the per-route head structure re-probed round 18; the description-template scope re-probed round 19 — the live head has changed three rounds in a row).** The body-DOM signature diff is structurally blind to the transport and `<head>` layers — probe them separately (curl-level). The pins: `next.config.ts` sends `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, `Strict-Transport-Security: max-age=31536000` (the live's edge trio) plus `X-Frame-Options: DENY` + `Permissions-Policy: camera=(), microphone=(), geolocation=()` (hardening additions) on `/:path*` with `poweredByHeader: false` (CSP is future work — a nonce strategy for Next's inline scripts); the live's head is PER-ROUTE STRUCTURED (round-18 probe): app pages (/, the views, 404s) render the plain viewport (NO viewport-fit, NO theme-color), a single bare icon link, a BARE og:image, and the full twitter description — ONLY `/login` carries `viewport-fit=cover` + `theme-color #000000` (via `buildRouteViewport` + the catch-all's `generateViewport`), the sized icon pair (`icon sizes="any"` + `apple-touch-icon sizes="180x180"`, via the seam's login-level `icons` — page-level icons REPLACE the layout's, same shallow-per-key merge as openGraph), and the og:image descriptor (width/height + the live's `alt "Base44 link preview"`; the dims describe OUR 480×480 asset — the live's 1200×630 describes its CDN render, asset values are deployment properties). The twitter block is explicit on every route (replacing Next's openGraph derivation): `card summary_large_image`, title = the document title, a BARE twitter:image (no dims), `twitter:url` = the absolute canonical via the `metadata.other` escape hatch (Next's Twitter type has NO url field; the dashboard url is the BARE origin — the canonical quirk), and a per-route description — the FULL `SITE_DESCRIPTION` on /, /Dashboard, /login and 404s but `{ViewLabel} on Finara. {SITE_DESCRIPTION.slice(0, 80)}.` on the eight non-dashboard view routes (a 98-char mid-word truncation, probed on all 8; round 19: the template now applies to the MAIN `description` and `og:description` metas TOO — the seam's `routeDescription` feeds all three description fields, one per-route string everywhere); the login twitter image carries the live's `alt "Base44 link preview"` (round 19 — app pages keep the bare twitter:image); `absoluteCanonicalUrl` builds the absolute URLs (siteBaseUrl normalizes trailing slashes). NO `keywords` meta anywhere (the live renders none). Per-route og:title/og:url via the `buildRouteMetadata` seam in `src/lib/route-metadata.ts` (og:title mirrors the document title; the DASHBOARD canonical normalizes to `/` — a live quirk; Next merges metadata SHALLOWLY per key, so the seam returns the COMPLETE openGraph block, not just per-route fields); `src/app/robots.ts` renders the live shape (`User-agent: *` + `Allow: /` + the `Sitemap:` line — the old per-bot `public/robots.txt` is DELETED, a public file would shadow the metadata route); `src/app/sitemap.ts` lists exactly the live's 9 URLs (`/` 1.0 + the eight non-dashboard views 0.8/weekly — NO `/Dashboard`, NO `/login`). The live's broken `manifest.json` link (302s to nothing) and its app-page icon `type="image/svg+xml"` mislabel (a PNG href) are deliberately NOT replicated; Next's `initial-scale=1` (vs the live's numerically identical `1.0`) is a documented framework micro-delta. `NEXT_PUBLIC_SITE_URL` (default `http://localhost:3000`) resolves metadataBase/og:url/sitemap URLs — set it in production. All pinned by `src/lib/__tests__/site-metadata.test.ts`.
- **Client components must not import server modules.** `src/lib/analytics.ts` and `src/lib/db.ts` pull in Prisma — importing them from a `"use client"` file ships the DB client to the browser. Pure helpers (`money`, `categories`, `types`) are safe; anything DB-touching stays server-side. `monthlyEquivalent` lives in `lib/money.ts` for exactly this reason.
- **AI Insights are PERSISTED records with generate-once-when-empty (round-13, live-probed).** The live loads `TransactionInsight` rows (`list("-created_date", 10)` filtered `!is_dismissed`) and dismisses with `update(id, {is_dismissed: true})` — generation is an EXTERNAL backend process, not the request path. The clone mirrors the mechanics: `GET /api/ai/insights` is a pure list that generates+persists ONLY when the Insight table is completely empty (dismissed rows still count — dismissing everything leaves the live's empty state showing; refresh re-lists, NEVER regenerates), guarded by the atomic `Setting._insights_generated` unique-key marker (same pattern as the seed lock). The deterministic drafts live in `src/lib/insights.ts` (pure seam; titles "Savings rate check"/"Top spending category"/"Spending exceeds income"/"Budget watch", ≤3 records); `dismiss` is `PATCH /api/ai/insights/[id] {is_dismissed: true}` (idempotent). The optional LLM polish joins polished text onto drafts POSITIONALLY via `mergePolishedDrafts` (the prompt pins order — a title-keyed join silently loses confidence/category when the LLM rewrites titles) and is env-gated (`FINARA_INSIGHTS_LLM_OFF=1` forces deterministic drafts; the E2E webServer sets it, production leaves it unset). Insight record TEXT keeps its creation-time currency — it is persisted content, not a live-rendered figure (the live's records behave the same).
- **The runtime DATABASE_URL resolves through `src/lib/db-path.ts` (round-21).** A RELATIVE `file:` SQLite URL anchors at `prisma/schema.prisma` (the CLI's own anchor, discovered by walking up from the process CWD) — so `.env`'s `file:../db/custom.db` points at `<repo>/db/custom.db` for `prisma db push`, `next build`, and the running server alike, regardless of the process working directory. ABSOLUTE `file:` URLs pass through unchanged (the Playwright webServer's hermetic `db/e2e.db` pin depends on this — never make the resolver rewrite them) and non-SQLite URLs pass through untouched; a missing `DATABASE_URL` throws the crisp setup error, not Prisma's raw constructor message. The contract is pinned by `src/lib/__tests__/db-path.test.ts`; `src/lib/db.ts` wires it through Prisma 6's `datasourceUrl` option.

## Framework quirks (verified the hard way)

- **React Compiler is on**: `react-hooks/set-state-in-effect` is an ERROR. No setState in effect bodies. For browser-storage-backed session state use the `useSyncExternalStore` pattern in `finara-app.tsx` (server snapshot renders the logged-out shape; client snapshot takes over post-hydration) — never a `useState` initializer (freezes SSR shape).
- **Memo deps must be stable references.** `useMemo(..., [expenses])` where `const expenses = query.data ?? []` mints a fresh array per render → `react-hooks/preserve-manual-memoization` fails compilation. Depend on `query.data` and derive inside the memo.
- **Next.js 16**: route handler `params` are async — `await context.params`. Page files may export only `default` + `metadata`/`revalidate`/`dynamic`.
- **Tailwind v4 is CSS-first**: design tokens live in `src/app/globals.css` `@theme inline` block; shadcn semantic tokens are literal oklch values. The v3-era `tailwind.config.ts` and the `tailwindcss-animate` dependency were DELETED in round-12 (referenced by nothing — animations come from `tw-animate-css` via CSS import); do not re-add a JS config — put theme values in `@theme inline`.
- **ESLint/tsconfig ignore `repos/`, `examples/`, `skills/`** — reference material only, not app code. Keep the ignores when adding sibling directories.
- **Deleting the SQLite file under a running server splits the connection pool** across the dead inode and the new file. To reset: stop the server, `rm db/custom.db`, `bun run db:push`, restart — or just `bun run db:reset`.

## Conventions that differ from defaults

- Strict TypeScript; `any` is avoided (use `unknown` + guards from `src/lib/api.ts`).
- Conventional Commits, atomic scope: `feat(expenses): …`, `fix(seed): …`. Never bundle unrelated changes.
- TDD for domain logic: write the failing `src/lib/__tests__/*.test.ts` first, implement in the pure module, then wire views/routes. `bun run test` is part of the pre-push gate.
- Errors are logged with a `[api]`/`[ai/*]` prefix server-side and returned as customer-safe strings — internals never reach the client.
- The login gate is a documented demo credential check (see README §Demo Credentials) — never present it as real authentication, and do not store credentials anywhere but the login screen constants.
- Demo data realism is a feature: seeded amounts jitter ±10%, categories/dates stay plausible. Keep it that way when editing `src/lib/seed.ts`.
- Rendering-time state adjustment (guarded `setState` during render) is the established pattern for "reset when inputs change" — NOT effects (React Compiler rejects setState in effect bodies). See `expenses-view.tsx` (filter-context reset) and `add-transaction-dialog.tsx` (edit prefill).
